# 小児用量ツール：PMDA最終突合プロトコル

この文書は、新しい薬剤・規格・剤形を追加するとき、および既存データを変更するときの必須ルールである。新しいチャットや担当変更後も同じ基準を使用する。

## 1. 完了条件

薬剤は、次の3方向が一致した場合にのみ `PMDA最終突合済み` とする。

1. **PMDA電子添文**：最新版の製品電子添文に記載された承認情報
2. **マスターデータ**：規格、剤形、濃度、適応、年齢・体重条件、用量、回数、上限、注意事項
3. **実際の判定画面**：入力値から算出・表示される製剤量、成分量、判定、警告

資料を読んだだけ、マスターを直しただけ、画面が表示できただけでは完了にしない。

## 2. PMDAで確認する必須項目

- 販売名、一般名、剤形、規格、濃度、1単位中の成分量
- 承認された効能・効果と、適応ごとの用法・用量
- 年齢、月齢、体重による対象条件と境界
- 1回量、1日量、投与回数、投与間隔、投与日数
- 1回上限、1日上限、成人量上限、増量条件
- 禁忌、原則投与しない条件、重要な年齢制限
- 規格固有の適応制限や、生物学的同等性に基づく代用不可条件
- 小児固有の承認用量が存在するか

根拠はPMDAの該当製品PDFへ直接到達できるURLを保存し、確認日と変更内容を薬剤単位で記録する。PMDA以外の資料は補助根拠として区別する。

## 3. 実装ルール

- 規格・剤形ごとに正しい `mgPerUnit` と製剤単位を持たせる。
- 成分量基準と製剤量基準を混同しない。散剤は必要に応じてg、液剤はmL、錠剤は錠、分包製剤は包で表示する。
- 適応、年齢帯、重症度などで承認用量が異なる場合は判定ロジックを分離する。
- 対象外条件は `NaN` 等の明示的な対象外値で返し、承認上限超過とは別の判定を表示する。
- 小児固有承認量がない薬剤は、成人量から換算せず参照情報として区分する。
- 添文上の注意と数値判定を分離し、判定範囲内でも必要な警告を消さない。
- 未突合レコードの一括昇格は禁止する。薬剤単位の根拠URLと監査メモが必須。

## 4. 必須テスト

各薬剤について、該当するものをすべて確認する。

- 年齢境界：直前、境界値、直後
- 体重境界：直前、境界値、直後
- 通常用量：下限、範囲内、上限
- 上限逸脱：1回上限超過、1日上限超過
- 投与回数・間隔：承認内と承認外
- 規格制限：使用可能規格と使用不可規格
- 製剤換算：成分量とg／mL／錠／包の相互換算
- 対象外：対象外判定が「上限超過」など別の理由に上書きされないこと
- 回帰確認：既存薬剤の代表例が変更前と同じ判定を維持すること
- 全JavaScriptの構文検査と `git diff --check`

テストで不一致が出た場合、PMDA最終突合済みにせず修正・再試験する。

## 5. 進捗管理

- 10薬剤ずつ監査する。
- 各10薬剤の完了時に `PMDA-FINAL-AUDIT-PROGRESS-2026-09.md` を更新する。
- 完了数／全139監査単位、百分率、残数、薬剤別の修正要点を報告する。
- 監査は会話ターンが変わっても同じキューから継続する。
- 現行139監査単位の完遂までは、新規薬剤追加を停止する。追加候補は提案・保留リストにとどめる。

## 6. 新規薬剤を追加するとき

1. 仮登録し、状態を未突合とする。
2. 最新PMDA電子添文を取得する。
3. 第2節の全項目を抽出し、剤形・規格単位でマスターへ登録する。
4. PMDA、マスター、判定画面を3方向照合する。
5. 第4節の境界値・換算・回帰試験を実施する。
6. 根拠URL、確認日、監査メモを保存する。
7. すべて合格後にのみ `PMDA最終突合済み` とする。
8. 10薬剤単位の進捗へ加え、総監査単位数も更新する。
